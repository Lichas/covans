# Covan 体验迭代 · 2026-09-08

本轮围绕真实 Electron 单聊、群聊和设置流程展开。设计参考方向是 Codex 的长文/代码阅读与操作反馈，以及 Grok Bot 的人格化、多 Bot 对话；并非对两款产品最新版本的逐项功能审计。

## 已完成

| 场景 | 改进 |
| --- | --- |
| 阅读回复 | Markdown 标题、强调、列表、引用、GFM 表格、任务列表、行内代码与代码高亮；表格/代码独立横向滚动 |
| 消息上下文 | 每条消息显示作者和时间；悬停可见完整日期；跨日分隔；生成中的消息保持真实 Bot 身份 |
| 消息操作 | 原文复制、代码复制（通过原生剪贴板）、引用回复、失败重试 |
| 输入 | 每个会话独立保存草稿，刷新后恢复；保护中文输入法确认；生成期间可以准备下一条消息 |
| 历史 | 主动加载更早消息并维持阅读位置；回到最新按钮；相同时间戳边界不漏消息 |
| 生成 | 显式的轮次开始/结束状态；思考占位；停止当前回复及剩余群聊队列；保留已输出内容；配置错误可见 |
| 导出 | 原生保存对话框导出完整 Markdown 会话，包含尚未加载到界面的历史消息 |
| 导航 | Covan 品牌与欢迎页；个人 Bot 卡片；新建入口；搜索清除/回车；恢复最后打开的会话 |
| 视觉 | 暖白/炭灰双主题，低饱和绿点缀；集中阅读宽度；浮动输入框；Bot 设置默认收起 |
| 键盘 | ⌘K 搜索、⌘1 新建 Bot、⌘2 群聊、⌘, 设置、⌘. 设置面板；弹窗焦点限制和 Esc 关闭 |
| 关于我 | 个人资料、偏好、目标、边界；带来源与时间的共同记忆，支持增加/编辑/删除，所有 Bot 后续对话自动引用 |
| Bot 设定 | 自然语言调用真实工具修改名称/人设/头像；本地 SVG 插画与可配置 Images API 生图两种方式；独立的提示词扩写 |
| 私聊 | Agent 咨询另一位 Agent，记录锚定当前用户消息，卡片内联显示，浮窗查看实际流式回复；支持停止与错误状态 |
| 置顶 | 单聊列表项右键置顶/取消置顶；顶部仅显示已置顶圆形头像，最多3位，后端同样限制 |
| 启动 | 根目录 start.command：Node 与 Electron 二进制检查、缺失依赖安装、原生 ABI 检查、启动开发模式 |
| 本地模型 | OpenAI 兼容 Provider 支持无 API Key；LM Studio 一键预设、模型动态拉取、误填完整 endpoint 自动规范到 /v1 |

技术备注：

- 原始 HTML 不执行，链接交给系统浏览器打开。远程 Markdown 图片展示为可点击链接。
- 保留现有应用数据路径与内部 IPC 命名，避免品牌变更使旧会话与 Provider 配置失联。
- 生成状态来自主进程事件，不再使用定时器猜测群聊是否结束。
- message-start 携带完整占位消息，generation-state 表示整个轮次；停止通过轮次级 AbortController 传递到协调者与当前 Agent。
- 历史数据查询保留同毫秒消息的插入顺序，并补齐分页边界上的同时间戳记录。
- 冒烟测试通过 Electron 的 Node 模式运行，与 better-sqlite3 的原生 ABI 保持一致。
- 头像协议改为合法的固定 host + 编码路径，并限制到 avatars 目录，修复原先编码斜杠放进 host 导致加载失败；上传和生成使用唯一文件名，避免缓存旧头像。
- 生图协议按官方 OpenAI 文档核对，配置由用户选择，不假设聊天 Provider 支持生图。实测覆盖本地 loopback 的 Models/Chat Completions/Images API；未调用付费图片服务。
- 私聊接收方不开放应用写入工具和递归私聊工具；重启后不恢复付费请求，将遗留进行中状态标为已停止。

## 验证

运行 `npm run typecheck`、`npm run smoke`、`npm run test:ui`、`npm run test:context`。

UI 回归使用独立临时 profile 和 Mock Provider，通过真实 Electron 页面、IPC、SQLite、原生剪贴板及文件导出验证。不会调用已配置的收费模型，也不会创建用户可见的测试会话。截图生成在 artifacts/ux/，该目录不进入 Git。

新增 context-ui 回归通过本地 OpenAI 兼容 HTTP 服务驱动真实 pi Agent 工具循环，验证改名→记忆→提示词扩写→头像生成→私聊及刷新恢复；另测三席上限、取消/错误私聊、共享资料注入、图片响应。截图在 artifacts/context/。

## 后续优先项

这些是下一轮候选功能，本轮未实现：

1. 消息编辑、重新生成与分支历史：需要把回复与来源消息/轮次明确关联，避免重试不断重复插入用户消息。
2. 图片和文件附件：补齐选择、预览、大小/格式限制、模型能力检测与请求传递；本轮移除了无作用的附件按钮。
3. 工具活动展示：把工作区读写等实际执行过程呈现为可折叠的活动记录。
4. 全文搜索与会话归档：当前搜索覆盖会话名和最近消息摘要。
5. 数学公式、Mermaid 图、可调字体与更细粒度的阅读偏好。

现有自动审核/通知等设置仍需端到端核对并补齐行为，不能把这些开关视为已实现的完整能力。
