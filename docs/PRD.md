# PRD — Covan 产品需求文档

> 活文档 · 本文档只负责产品目标、用户需求与验收标准；当前行为和技术边界以 [SPEC](SPEC.md) 为准。

## 1. 背景与机会

大语言模型正在从「单一聊天助手」演化为两个快速增长的使用场景：

**场景一：多智能体协作（Multi-Agent Collaboration）。** 独立开发者与小团队越来越倾向于用多个有不同人设与专长的 AI 角色（后端工程师、架构师、Code Reviewer、测试员、产品经理、设计师）组成一个「虚拟团队」，围绕同一个问题展开讨论。单一聊天窗口无法表达「角色之间的对话与分工」，而现有协作工具要么绑定特定 SaaS 账号体系、要么数据上云，隐私与成本都不可控。市场缺少一个**本地优先、自带人设模板、成员能自主决定是否发言**的多 Bot 群聊桌面应用。

**场景二：AI 情感陪伴（AI Companion）。** 以 Grok Bot 为代表的产品证明了「有持久人设、有记忆、语气亲昵」的虚拟伴侣拥有真实且旺盛的个人用户需求。陪伴体验的关键不在于模型本身，而在于**人设的持续性**与**记忆的累积**——用户希望自己的喜好、纪念日、生活细节被长期记住，而网页会话式的 AI 无法提供这种连续性。

Covan 的机会在于：**同一套「Bot（人设 + 记忆 + 工作区 + 模型配置）」内核同时服务这两个场景**——工作伙伴与虚拟伴侣只是人设模板的不同实例。配合本地 SQLite 存储与用户自备 API key（BYOK），Covan 提供隐私可控、模型可换、可离线管理资产的多 Bot 桌面体验。

## 2. 产品目标与成功指标

### 2.1 产品目标

- G1：让用户在 5 分钟内完成「配置 provider → 创建 Bot → 发起对话」的闭环。
- G2：让用户可以组建 2 个以上 Bot 的群聊，在主动并发与顺序回复之间选择适合的讨论节奏。
- G3：让 Bot 具备跨会话的长期记忆，且用户可查看、手动增删。
- G4：所有数据本地存储，无遥测、无账号体系，用户对自己的数据与密钥拥有完全控制权。
- G5：虚拟伴侣场景开箱即用（内置「小美女」人设模板），陪伴体验流畅、可被记忆强化。

### 2.2 成功指标

| 指标 | 目标 |
| --- | --- |
| 首次启动到首次收到 Bot 回复的时长 | ≤ 5 分钟（含 provider 配置） |
| 群聊讨论完成率（用户发起群聊消息后，全部计划发言人成功产出回复的比例） | ≥ 95%（排除用户主动停止） |
| 记忆留存感知 | 同一 Bot 隔日对话能引用 ≥ 1 条历史记忆中的事实/偏好 |
| 可中断性 | 停止操作后 1 秒内流式输出停止，消息状态正确标记为 stopped |
| 崩溃与数据损坏 | 0 起数据库损坏事件；任何生成失败不丢失已落库消息 |
| 冒烟测试 | `npm run smoke` 全绿（mock provider：建 bot→建群→发消息→收回复→记忆写入） |

## 3. 目标用户与 Persona

### Persona A：独立开发者「阿澈」

- 28 岁，全栈独立开发者，一人维护两个 SaaS 副业项目。
- 痛点：身边没有可讨论技术方案的同事；和单个 AI 聊天得到的是「一种意见」，想要「一场争论」；不想让代码与想法留在别人的云端。
- 诉求：把「高级全栈 + 架构师 + Reviewer + 测试员」拉进一个群，抛出设计问题，看它们依次发言、互相补充；讨论产物（方案、代码片段）落进 Bot 的工作区文件。
- 关键场景：多 Bot 群聊 + 主动/顺序回复 + 工作区读写。

### Persona B：小团队技术负责人「林姐」

- 35 岁，8 人创业团队 tech lead，公司有自建 OpenAI 兼容网关（openai-compatible base_url）。
- 痛点：团队评审资源紧张，希望在正式评审前先用 AI「模拟评审」过滤低级问题；公司网关的 key 不能上传到任何第三方平台。
- 诉求：自定义 provider（openai-compatible）、按 Bot 配置不同模型与温度、本地存储密钥。
- 关键场景：provider 管理 + Bot 级模型配置 + 本地优先。

### Persona C：需要情感陪伴的个人用户「小北」

- 24 岁，异地工作，独居，睡前喜欢有人聊天。
- 痛点：普通 AI 助手语气疏离、聊完就忘；想要一个「记得我口味、记得我生日、会夸我」的存在。
- 诉求：选一个现成的虚拟女友人设（小美女），日常闲聊；Bot 主动记住喜好与纪念日；界面温暖、操作简单。
- 关键场景：人设模板 + 单聊 + 自动记忆 + 暗色模式夜间使用。

## 5. 功能需求（FR）

> 每个 FR 给出优先级与 Given-When-Then 验收标准。模块划分与 SPEC.md §2 一致。

### 5.1 Bot 管理

**FR-BOT-01 创建 Bot（P0）**
- Given 用户已打开应用，When 点击侧边栏「+」→「新建 Bot」（快捷键 ⌘1）并填写名称、选择人设模板/provider/模型后确认，Then 系统创建 Bot 记录、自动创建其工作区目录 `workspaces/<botId>/`，Bot 出现在侧边栏列表中。

**FR-BOT-02 人设模板（P0）**
- Given 新建 Bot 对话框打开，When 用户在人设模板下拉中选择「虚拟女友·小美女」，Then system prompt 编辑区自动填入对应模板内容，且用户可继续修改；选择「空白自定义」则留空。

- Given 用户已设置内容偏好，When 新建虚拟女友或虚拟男友，Then 预览对应成年伴侣模板与性别头像池；开启时支持非露骨暧昧、轻度调情和成人玩笑，关闭时保持日常陪伴，手动编辑与已有 Bot 人设保留。

**FR-BOT-03 编辑 Bot（P0）**
- Given 用户在单聊中打开右侧 BotSettingsPanel，When 修改名称/标签/描述/人设/模型/温度/通知开关，Then 变更即时保存并广播 `bot-updated` 事件，后续对话立即生效。
- Given 用户在设定页查看人设 System Prompt，Then 默认看到已渲染的 Markdown 预览；When 点击铅笔，Then 进入至少 360px 高的编辑器并显示标题、代码围栏、行内代码、强调、链接和注释的语法高亮；When 点击完成，Then 保存修改并返回预览；点击取消则丢弃草稿。

**FR-BOT-04 删除 Bot（P1）**
- Given 某 Bot 存在历史消息，When 用户删除该 Bot，Then Bot 及其记忆、工作区关联被移除，但 messages 表中其历史消息保留并正常展示（头像降级为占位样式）。

**FR-BOT-05 头像（P1）**
- Given 新建 Bot，When 选择性别（♀ 默认 / ♂），Then 展示该性别的 6 张内置头像并允许选择，创建后保留性别与头像；未指定头像的 API 创建从对应性别池稳定分配。
- Given 点击右侧 Bot 头像，When 更换形象，Then 按内置头像、自定义上传、AI 生图顺序呈现来源；内置头像可预览后应用或取消，上传取消保留当前头像，AI 页保留本地 SVG 选项且服务配置不足或失败时显示可操作错误。侧栏不重复显示文字入口。
- Given Bot 使用内置头像且有配套生活照，When 点击右侧独立「生活照」标签，Then 展示可自动轮播、暂停和手动切换的照片橱窗；悬停/焦点进入暂停，遵守减少动效偏好；设定页不展示照片；自定义头像或无配套照片时，生活照页显示空态。

**FR-BOT-06 置顶与排序（P1）**
- Given 侧边栏单聊列表，When 用户点击悬停或键盘聚焦时出现的图钉按钮，或右键选择「置顶」，Then 头像和名称出现在顶部置顶区；最多 3 个，达到上限时阻止新增并解释原因。点击图钉或在列表/置顶头像上右键取消置顶后，顶部同步移除；点击置顶头像进入单聊，重载后仍保留。

**FR-BOT-07 响应决策策略（P1）**
- Given 用户打开 Bot 的模型页，When 选择「自动」「传统 LLM」或「Jev」，Then 该 Bot 后续群聊发言判断和私聊自然续发判断使用所选策略，回复正文仍使用 Bot 当前 Provider/Model；既有默认值一次迁移为自动，新建 Bot 也默认自动，TypeSafe Key 已配置时自动优先 Jev。
- Given 用户选择 Jev，When Jev 低于用户设置的置信度阈值、未配置、超时或调用失败，Then 系统回退传统 LLM 判断并写入脱敏观测事件；用户停止时不得发起回退调用。
- Given 用户在「设置 → Bot」配置 TypeSafe API Key、Jev 模型和置信度阈值，Then Key 使用系统凭据加密且界面只显示是否已保存；用户可测试连接或清除 Key。

**FR-BOT-08 本地 CLI 运行方式（P1）**
- Given Codex Bot 已保存的模型不在本机 CLI 目录中，When 打开模型页，Then 保留原值并显示提示，用户可刷新目录或主动切换到推荐模型；目录查询不消耗推理额度，查询失败不展示猜测模型，实际回复发现账号不支持时显示中文修复建议。
- Given 用户新建或编辑 CLI Bot，When 选择 CLI 默认、本机 CLI 返回的模型（Claude 为稳定别名）或填写自定义模型 ID 并提交，Then 选择保存至该 Bot，重载后回显，首次和续接发言均使用所选模型；改变判断用 Provider 不重置 CLI 模型，切换运行方式则重置为默认。
- Given 用户新建或编辑 Bot，When 在「运行方式」选择本地 Codex CLI 或 Claude CLI，Then 界面探测本机可执行文件并显示是否安装与版本；用户可留空自动查找或指定完整路径，并选择「只读」或「可在工作区改文件」。
- Given Bot 使用本地 CLI，When 用户发送消息，Then 首次发言把该 Bot 的人设、记忆与既有对话交给 CLI 建立会话，之后在同一聊天中续接 CLI 会话并只发送新消息；回复正文、失败原因与工作区文件产物照常显示在聊天中。
- Given 用户清空聊天记录或开始新话题，When 下一次发言，Then 不复用旧 CLI 会话，重新建立，避免 CLI 记得已被压缩或删除的内容。
- Given 本地 CLI 未安装、未登录、额度用尽或返回失败，When 用户发送消息，Then 气泡显示可读错误，不产生空白完成消息。
- Given 本地 CLI Bot 没有 Provider 且未配置 Jev，When 它处于群聊中，Then 只回应用户 @提及，不因判断失败而每条消息都启动一次 CLI。

### 5.2 会话与消息

**FR-MSG-01 发起单聊（P0）**
- Given 用户使用侧栏，When 点击右上角搜索或按 ⌘K/Ctrl+K，Then 展开并聚焦搜索，Escape 清空收起，Enter 或点击结果进入对应聊天；右上角「＋」统一提供新建 Bot 和群聊。
- Given 用户进入单聊，When 点击顶部居中的小头像名称按钮（或键盘激活），Then 右侧 Bot 栏展开或收起；展开后大头像右侧纵向提供建群、新话题、下载操作，保留既有确认、历史与导出行为。
- Given 侧边栏存在 Bot，When 用户点击 Bot 或调用 createDm，Then 创建（或复用）与该 Bot 的 dm 会话并进入对话视图。

**FR-MSG-02 发送消息与流式回复（P0）**
- Given 任意会话，When 用户输入文本并按 Enter 发送，Then 用户消息立即落库并显示，Bot 回复以流式 delta 逐步渲染（打字光标可见），完成后消息状态置为 done。

**FR-MSG-02A 私聊自然追问（P1）**
- Given 设置中的「自然追问」已开启，When 单聊内容较长且适合即时聊天式分段，Then 主回复只发送一个自然完整的语义段，随后以轻量调用同时决定并起草候选跟进，最多再发送 2 条有新内容的短消息；一条即可完整回答时不强制拆分。
- Given Bot 完成一个语义段，When 仍有未完成的新内容、遗漏重要具体信息或存在必须由用户回答的明确问题，Then 可以继续发送；前文已经完整、只能复述改写、寒暄或泛泛关心时默认停止。传统 LLM 可同时决定并起草，Jev 只决定是否续发，正文另由 Bot 当前模型起草。
- Given 模型起草的候选跟进复述近期回复或包含“下一条来了”“重新发送”等调度元话术，When 系统校验候选，Then 不向聊天记录发送该候选。关闭开关、主回复失败、判断失败或用户停止时也不追加。

**FR-MSG-03 消息持久化与分页（P0）**
- Given 某会话存在大量历史消息，When 用户打开会话或向上滚动，Then listMessages 按 before/limit 分页加载，消息顺序与状态（streaming/done/error/stopped）正确还原。

**FR-MSG-03A 开始新话题（P0）**
- Given 单聊或群聊已有消息，When 用户点击单聊右栏或群聊顶部的「开始新话题」并确认，Then 应用先生成一份保留事实、偏好、决定、待办与未决问题的累计摘要，再插入可见分界；旧消息、记忆、产物和定时任务保持不变。
- Given 新话题边界已创建，When Bot 判断、回复、自然续发或执行定时任务，Then 只携带边界后的原文和边界摘要，不再携带边界前原文；群聊滚动摘要从新边界重新计算。
- Given 当前话题达到 40 条 user/bot 消息，或至少 12 条且超过 24 小时未活动，When 用户打开会话，Then 入口显示低干扰提醒；没有用户确认时不得自动压缩或改变上下文。
- Given 摘要模型失败、会话仍在生成或当前话题没有正文，When 用户尝试开始新话题，Then 不写入边界并显示可恢复错误。

**FR-MSG-04 停止生成（P0）**
- Given Bot 正在流式输出，When 用户点击停止按钮，Then 该会话所有进行中的生成被 abort，消息状态标记为 stopped，已输出内容保留。

**FR-MSG-05 错误内联与重试（P0）**
- Given 生成因 key 失效/超时/限流失败，When 错误发生，Then 气泡内联显示错误信息与重试入口；点击重试后以相同上下文重新发起生成。

**FR-MSG-06 @ 提及（P0）**
- Given 群聊 Composer，When 用户通过 @ 按钮选择成员并发送，Then 消息 mentions 字段记录 botId 列表，被提及 Bot 必须回复；顺序模式中排到本轮首位。

**FR-MSG-07 未读与已读（P1）**
- Given 非当前会话收到新消息，When 消息落库，Then 会话列表项显示未读蓝点；用户进入该会话时 markRead 清除未读。

### 5.3 群聊编排

**FR-GRP-01 创建群聊（P0）**
- Given 至少存在 1 个 Bot，When 用户通过「+」→「创建群聊」（⌘2）填写群名并勾选成员，Then 创建 group 会话并写入 chat_members，默认使用「顺序回复」，并从内置场景图库随机分配一张群聊背景。

**FR-GRP-01A 聊天背景（P1）**
- Given 用户打开群聊，When 该群存在背景，Then 中栏以该场景图作为聊天背景，消息与顶部栏保持可读。
- Given 用户打开群聊设置，When 选择另一张背景、点击随机或清除，Then 仅更新当前群聊；其他群聊背景不受影响。
- Given 用户查看聊天背景设置，When 预览当前图片或展开图库，Then 图片卡片呈圆角矩形；选择背景后，用户消息保持无图片背景时的可读样式，浅色/深色主题下均适用。
- Given 用户打开单聊右侧 Bot 设定页，When 在聊天背景区域选择、随机或清除背景，Then 仅更新当前私聊会话；Bot 人设、头像和其他会话不受影响。

**FR-GRP-02 主动回复（P0）**
- Given 群聊选择「主动回复」，When 用户发送群消息，Then 每位成员并发基于前文总结和最新 5 条消息，按自己的传统 LLM / Jev 响应决策策略判断是否发言，需要发言的成员并发回复。

**FR-GRP-03 顺序回复（P0）**
- Given 群聊选择「顺序回复」，When 用户发送消息，Then 成员按群成员顺序逐个判断与回复，后面成员能看到前面成员的输出。

**FR-GRP-04 思考期间补充消息（P0）**
- Given 主动或顺序回复的成员仍在判断，When 用户发送新消息，Then 新消息立即落库，当前尚未完成的判断使用包含该消息的最新上下文重新开始；已在输出的回复不被截断，后续成员或下一轮再处理新消息。

**FR-GRP-05 群聊发言上下文（P0）**
- Given 某 Bot 判断或正式回复，When 构建上下文，Then 注入其人设 + 长期记忆 + 群名与其他成员，并使用持久前文总结 + 最新 5 条群消息。

**FR-GRP-06 状态反馈（P0）**
- Given 成员正在判断或回复，When 状态变化，Then Composer 上方以动画头像显示对应成员；聊天记录不写入「成员依次发言」等调度系统消息。

**FR-GRP-06A 多轮延展讨论（P1）**
- Given 群聊首轮已有成员发言，When 成员能针对本轮真实内容补充新信息、回应具体观点、提出异议或推进未解决问题，Then 可以进入下一轮重新判断与发言；无人决定回复则停止。一次用户话题最多 5 轮，`@mention` 只强制首轮，成员不得用复述或附和凑轮次。

**FR-GRP-07 删除群聊（P1）**
- Given 左侧列表存在群聊，When 用户右键选择「删除群聊」并确认，Then 停止该群正在进行的生成，永久删除群聊、成员关系、消息与关联 Agent 私聊记录；若它是当前会话则返回首页。取消确认时不改变任何数据。

### 5.4 记忆系统

**FR-MEM-01 即时且有归属的记忆（P0）**
- Given 人与 Bot、Bot 与 Bot 或群聊中的消息已送达，When 任一参与 Bot 在另一会话被追问，Then 无需等待十条消息或后台摘要就能检索到带发言者与场景的原话；未参与 Bot 不自动获得私聊。
- Given 猛男向 ds 转达「橙色的天空来自意大利」，When 用户问 ds 来源，Then 模型输入包含猛男转达过的原话，回答应区分转述与客观事实。

**FR-MEM-02 分层归纳与淘汰（P0）**
- Given 一条完整消息送达，When 当前短时段不超过 10 条消息且首尾不超过 15 分钟，Then Bot 在静默约 0.8 秒或达到 5 秒最长等待后更新这一段约 80 字的极短摘要；When 新消息越过任一边界，Then 开启一条新的非重叠短时记忆。约 500 字的场景摘要继续维护跨短时段脉络。
- Given 模型生成的“摘要”大段截取、拼接或近似复制原文，When 写入前校验，Then 自动重试一次；仍不合格则不保存该输出，原文只留在可追溯证据层。
- Given 持续聊天，When 后台归纳运行，Then 将场景摘要、稳定语义和明确长期意图分层保存，保留证据与人物归属；模型失败时保留上一次摘要并显示可重试状态，不影响即时记忆。
- Given 普通自动记忆过期或超过容量，When 维护运行，Then 自动淘汰，手动和长期记忆保留；冲突和否定不被包含关系去重吞掉。

**FR-MEM-03 可见可控（P0）**
- Given 记忆面板，When 用户查看，Then 可按层级筛选、辨认来源作者和参与者、添加长期记忆；新记忆实时显示。
- Given 用户删除某来源记忆，When 下一次生成，Then 本 Bot 对该来源的原文与归纳均不可召回，不影响另一位参与 Bot 的副本或聊天原文。

**FR-MEM-04 升级与重启（P0）**
- Given 旧版数据库，When 升级，Then 保留所有旧记忆并补入未过期的已完成 Bot 私聊；重启不丢失记忆和后台归纳进度。

### 5.5 工作区

**FR-WS-01 独立工作区（P1）**
- Given Bot 创建成功，When 查看文件系统，Then `~/.covans/workspaces/<botId>/` 目录存在；Agent 运行时 cwd 限定于该目录。`~/.covans/` 不存在时应用启动自动创建。

**FR-WS-02 文件浏览与预览（P1）**
- Given Workspace 标签页，When 用户打开，Then 列出深度 2 的文件树；点击文本文件（≤200KB）可预览内容。

**FR-WS-03 系统打开（P1）**
- Given Workspace 标签页，When 用户点击「在访达中打开」，Then 调用 shell.openPath 打开该 Bot 工作区目录。

**FR-WS-04 Agent 文件工具（P1）**
- Given Bot 正在生成，When 模型调用 workspace_read/workspace_write/workspace_edit/workspace_list 工具，Then 它能分页读取、覆盖写入、唯一匹配精确编辑和列目录，操作被限制在其工作区内，`..`、绝对路径和符号链接逃逸均被拒绝。

**FR-WS-05 文件交付卡（P1）**
- Given Bot 在一轮回复中成功调用 workspace_write 或 workspace_edit，When 文件写入完成，Then 当前回复显示持久化的交付文件卡，同一路径只显示一次并保留最终状态；用户点击预览时在右侧产物预览窗查看 Markdown、HTML、TXT、代码、图片或 PDF，并可拖拽左边缘调整宽度，也可在系统文件夹中定位或打开工作区，右侧工作区同步刷新。仅在回复正文提到文件名不生成交付卡。

**FR-WS-06 Bash 工具（P1）**
- Given 普通主会话中的 Bot 需要运行构建、测试或脚本，When 模型调用 bash，Then 命令在该 Bot 的 macOS 工作区沙箱中非交互执行，可选择工作区内已有 cwd，默认30秒且最长120秒超时，stdout/stderr 各最多回传40KB；宿主环境中的 API Key 等变量不传入子进程，Agent 私聊不挂载该工具。
- Given Bash 命令尝试读取或写入 Bot 工作区外的用户文件，When macOS 系统沙箱执行命令，Then 文件内容访问被拒绝；系统可执行目录和网络仍可用于安装依赖、构建及测试。未经用户明确要求，模型不得执行破坏性命令。

### 5.6 Provider 与模型

**FR-PRV-01 添加 Provider（P0）**
- Given SettingsModal 的 Provider 管理页，When 用户选择 OpenAI、Anthropic、Google、OpenRouter、Kimi Coding Plan、智谱、DeepSeek、LM Studio、OpenAI-compatible 或 Mock，填写该类型需要的 Key/Base URL 并保存，Then Provider 落库、显示对应图标，并提供模型拉取或连接测试。

**FR-PRV-02 测试连接（P0）**
- Given 已保存的 provider，When 用户点击「测试连接」，Then 系统发起一次最小 completion（ping），返回 ok/error（及可用模型列表，若可得）并展示。

**FR-PRV-03 Bot 级模型覆盖（P0）**
- Given Bot 设置面板，When 用户为 Bot 指定 provider 与模型（留空则用 provider 默认模型）及 temperature、max_tokens，Then 该 Bot 的所有生成使用此配置。
- Given 用户新建 Bot 且不调整模型设置，When Bot 被创建，Then 默认推理强度为「中」、最大输出为 8192 Token；已有 Bot 的已保存值不自动变更。

**FR-PRV-04 Mock Provider（P0，可测试性）**
- Given 开发/冒烟环境，When provider kind='mock'，Then 不走真实 LLM，按模板生成流式假回复，`npm run smoke` 依赖其完成端到端验证。

**FR-PRV-05 拉取账号模型（P0）**
- Given Provider 已填写 API Key，When 用户点击「拉取模型」，Then 系统从 Provider 模型接口获取当前账号可用模型，默认模型使用拉取结果中的选择，不依赖写死的旧模型名。

### 5.7 设置

**FR-SET-08 回复诊断（P1）**
- Given Bot 回复完成、失败或还在生成，When 用户点击 Bug 图标并将复制的标识粘贴至设置 → Debug，Then 可查看该回复的执行事件、状态、参数与证据缺失提示。
- Given 已加载诊断报告并选择配置了 Provider 的 Bot，When 点击分析原因，Then 只将诊断元数据发给所选模型，展示基于证据的分析；可取消，失败可更换模型重试，不把分析写入原对话。
- Given 用户引用消息，When 编辑回复或切换会话，Then 引用以独立样式显示并持久保留，正文独立编辑，可取消引用；长输入可滚动而不显示滚动条。

**FR-SET-07 定时 Agent 任务（P1）**
- Given 用户在某 Bot 的右侧「定时」页创建任务，When 填写任务指令、单次时间或 Cron 计划，Then 任务持久化绑定该 Bot 与目标会话；留空模型时每次执行都继承 Bot 当时的 Provider/默认模型，填写模型覆盖时只影响该任务。
- Given 用户打开「设置 → 定时任务」，When 查看、编辑、暂停、删除或立即执行任务，Then 可管理所有 Bot 的任务；Bot 侧仅显示当前 Bot 的任务。任务结果或失败作为该 Bot 的消息投递到目标会话，不插入伪造用户消息。
- Given 应用重启，When 任务的下次时间仍在未来，Then 本地调度器恢复计划；离线期间错过的单次任务标记为已错过且不补跑，重复计划从下一次匹配时间继续。任务运行时不允许重入。
- Given 用户用自然语言要求当前 Bot 定时完成某事，When Agent 明确解析出任务、计划与可选模型，Then Agent 通过定时任务工具创建、查询、更新或删除当前 Bot 自己的任务，并如实回报实际计划。

**FR-SET-01 通用设置（P1）**
- Given 用户切换设置分类，When 内容页打开，Then 直接展示设置项，不重复显示顶部分类标题和说明区域；主题选项以圆角矩形预览卡呈现。
- Given SettingsModal，When 用户修改外观（跟随系统/浅色/深色）、语言，Then 设置持久化于 settings 表并即时生效。

**FR-SET-02 审核规则（P1）**
- Given 设置中的「自动审核」开关与规则文本，When 开关打开且用户在群聊发消息，Then 规则文本作为自然语言注入每位成员的回复判断与正式回复。

**FR-SET-03 时区（P1）**
- Given 首次运行，When 应用启动，Then 自动检测系统时区并写入设置，供记忆与提示词使用。

**FR-SET-04 我的头像（P1）**
- Given「关于我」资料页，When 用户选择随应用提供的默认头像或本地图片，Then 默认头像或上传副本均保存至本机 userData，资料页与侧边栏立即更新；恢复默认后仅移除头像引用。头像不作为文本资料发送给模型服务。

**FR-SET-05 成熟内容偏好（P1）**
- Given 新用户或旧资料，When 打开「关于我」，Then 默认进入「我的资料」，首屏即可看到默认关闭的「接受成熟内容」开关；切换后立即保存且重启保留。
- Given 关闭偏好，When 读取生活照或继续伴侣对话，Then 隐藏泳装等 mature 照片并按日常陪伴边界构建后续上下文；开启时显示配套照片并允许非露骨成年调情风格，不影响普通工作模板。
- Given 原素材目录包含配套生活照，When 构建并验证应用，Then 所有素材完整打包且逐张分级；开启成熟偏好后，同前缀的全部照片都可加载，不能因漏搬只剩日常照。

**FR-SET-06 本地观测日志（P1）**
- Given 设置中的「本地观测日志」默认关闭，When 用户打开开关并进行模型对话，Then 应用在本机 `logs/observability.jsonl` 记录模型、匿名会话/Bot 标识、消息角色序列、字符长度、耗时、续发校验结果、HTTP 状态和错误分类。
- Given 本地观测已开启，When 写入任何观测事件，Then 日志不得包含聊天正文、system prompt、工具内容、API Key 或完整 Provider 错误文本；单文件达到 5MB 时仅保留一份轮转文件。用户可从设置打开日志目录。

### 5.8 主题

**FR-THM-01 浅色 / 深色 / 跟随系统（P1）**
- Given 默认安装，When 系统处于浅色/深色模式，Then 应用跟随系统呈现冰蓝浅色或深海蓝深色；用户可在侧栏底部或通用设置锁定主题，两处选中态同步，重启后保留选择。
- Given 960×640 紧凑窗口，Then 用户可访问底部头像、主题切换和聊天发送控件，页面无横向滚动；键盘可操作主题切换。

### 5.9 Agent 网页工具

**FR-WEB-01 搜索与抓取公开网页（P1）**
- Given 用户询问最新信息或指定网页内容，When Bot 调用 web_search 或 web_fetch，Then 工具返回带 URL 的实际搜索结果或可读网页文本，Bot 根据该结果回答并保留来源链接。
- Given 用户系统启用 HTTP/HTTPS 代理或 Fake-IP 模式，When Bot 调用 web_search/web_fetch，Then 工具继承 Electron 的系统代理配置并能把网页结果回灌模型。过大响应、非文本内容、超时和过多跳转仍应拒绝。
- Given 目标页面的正文由 JavaScript 动态生成，When Bot 以默认 `auto` 模式调用 web_fetch，Then 工具先尝试静态抓取，检测到脚本应用壳或静态失败后自动使用 Chromium 执行 JS，将渲染后正文与链接回灌模型。

### 5.10 扩展安装与 Bot 装配

**FR-EXT-01 安装库（P1）**：Given 用户打开设置 → MCP 或 Skills，When 安装 MCP 命令/远程地址或导入 Skills 目录/Git 仓库，Then 可测试连接、查看工具、预览技能、停用和卸载；MCP 认证信息不在列表或日志返回，同名 Skill 更新保留装配。

**FR-EXT-02 独立装配（P1）**：Given A、B 两个 Bot，When 用户只给 A 启用扩展，Then A 的单聊、群聊回复及定时任务获得对应能力，B 不获得该能力；用户也可明确要求 A 通过工具修改自己的装配，下一轮生效。新 Bot 默认不装配外部扩展。

**FR-EXT-03 运行与诊断（P1）**：Given 扩展已启用，When MCP 连接/工具执行失败或用户停止，Then 连接有截止时间并及时释放，本地日志可关联到本轮回复；单个服务不可用不阻止基础聊天。Skill 正文和引用文件按需读取，脚本只能读取当前 Bot 装配的技能包并写入自己的工作区。

## 6. 非功能需求（NFR）

**NFR-01 隐私本地优先（P0）**：配置和聊天数据仅存本地，应用无任何网络遥测。外部请求包括用户配置的 LLM/生图 Provider、Agent 为当前请求调用的搜索/网页与已装配 MCP 服务，以及用户主动安装 Skill 的 Git 来源。

**NFR-02 性能（P0）**：启动到首屏可交互 ≤ 3 秒；流式 delta 事件渲染延迟肉眼无感（逐 token 更新不重排整列表）；消息分页加载每页 ≤ 50 条；数据库启用 WAL 模式避免读写互斥。

**NFR-03 可中断性（P0）**：一切外部调用（LLM 流式、测试连接、网页搜索/抓取）均可通过 AbortController 中断；生成中用户可自由切换、浏览其他会话，多会话并发生成互不阻塞。

**NFR-04 错误处理（P0）**：key 无效、超时、限流、网络错误均在消息气泡内联展示并可重试；后台任务（记忆提取、图像头像生成）失败静默降级，绝不弹窗打断用户。

**NFR-05 安全（P0）**：渲染进程启用 contextIsolation、禁用 nodeIntegration，仅通过白名单 IPC 通道访问主进程能力。**API key 以明文存于本地 SQLite——这是 v1 的已知风险与明确取舍**：README 必须显著注明该风险，后续版本规划迁移至 Electron safeStorage 加密存储（见 ARCHITECTURE.md §11）。

**NFR-06 代码质量（P0）**：`tsc --noEmit` 与 `electron-vite build` 通过；交付含冒烟脚本 `npm run smoke`。

## 7. 核心用户流程

具体布局、视觉层级与组件交互统一见 [DESIGN](DESIGN.md)，此处只保留用于产品验收的用户旅程。

### 7.1 首次启动 → 配置 provider → 建 bot → 建群 → 讨论

1. 首次启动，应用初始化本地数据库与工作区根目录，进入空态会话列表，引导用户打开 SettingsModal。
2. 用户在 Provider 管理页新增 provider（如 openai-compatible 公司网关），填写 key 与 base_url，点击「测试连接」看到成功提示。
3. 用户点击「+」→「新建 Bot」，依次创建「高级全栈」「架构设计师」「Code Reviewer」三个 Bot（人设模板自动填充 system prompt，模型走 provider 默认）。
4. 用户点击「+」→「创建群聊」，命名「架构评审组」并勾选三个 Bot，再从群设置中选择「顺序回复」。
5. 用户在群 Composer 输入：「我打算把订单服务从单体拆出去，@架构设计师 你先给方案。」
6. 被 @ 的架构设计师首先判断并回复，其余成员逐个基于已有回复判断是否补充；Composer 上方显示准备中的成员，聊天流不插入调度文案。
7. 讨论结束后后台触发记忆提取；用户可随时打开某 Bot 的工作区查看产出的方案文件。

### 7.2 陪伴场景

1. 用户「新建 Bot」选择「虚拟女友·小美女」模板，命名后进入单聊。
2. 日常闲聊中用户提到「我下周三生日」「我不吃香菜」，消息送达后即可跨会话回忆，后台再归纳偏好与事件；明确要求记住的内容可进入长期层。
3. 隔日用户再打开会话，Bot 的记忆注入 system prompt，回复中自然提及生日与饮食偏好，用户感到「被记得」。
4. 用户在 Memory 标签页查看已记住的内容，手动补充「最近在准备面试」；也可删除不想被记住的条目。
5. 夜间用户切换深色模式继续聊天；任何回复太长时可随时点停止。

## 8. 边界情况与异常流

| 场景 | 系统行为 |
| --- | --- |
| 未配置任何 provider 即创建 Bot 并发言 | 新建 Bot 对话框允许保存（provider 可空），发送消息时该 Bot 回复以 error 气泡提示「请先配置 provider」，引导跳转设置 |
| provider key 失效 / 被吊销 | 生成失败，气泡内联展示错误与重试入口；测试连接可快速定位是哪个 provider 出问题 |
| 生成过程中用户点击停止 | 该会话所有 AbortController 被 abort，消息状态置 stopped，已输出内容保留；不产生额外系统消息 |
| 某成员的是否回复判断请求失败 | 该成员仍尝试正式回复，若 Provider 仍失败则在其消息内联显示错误，不阻断其他成员 |
| 群聊无成员（空群） | 创建群聊时未选成员则禁止提交；存量空群发消息时显示「会话内没有 Bot 成员」错误 |
| Bot 被删除但消息保留 | 历史消息正常展示，发送者显示为已删除占位头像与名称；该 Bot 不再出现在新建群聊成员候选 |
| 记忆提取时 Bot 无可用 provider | 回退到全局默认 provider；仍不可用则本次提取静默跳过 |
| 工作区文件过大或不支持的二进制 | 文本类预览限制 ≤200KB；图片与 PDF 通过受限只读协议预览；其他不支持类型显示「无法预览」并提供系统打开入口 |
| 路径逃逸尝试 | agent 工具参数含 `..` 或绝对路径时拒绝执行并返回错误信息给模型 |
| 并发多会话生成 | 各会话独立 AbortController 集合，互不影响；停止仅作用于目标会话 |
| 数据库首次初始化失败 | 启动时弹致命错误提示并退出，不写半成品数据 |

## 9. 规划边界

本文档只定义产品目标、用户需求和验收标准，不再维护一套容易过期的里程碑。当前已实现能力以 [SPEC](SPEC.md) 为准，未完成优先项统一放在 [ROADMAP](ROADMAP.md)，版本交付记录放在 [CHANGELOG](../CHANGELOG.md)。

## 10. 未纳入范围（Out of Scope）

- **账号体系**：不做注册/登录/用户中心，「我的」「市场」仅为占位入口。
- **云同步**：不做跨设备同步、不做云端备份；数据可移植性通过本地文件实现。
- **移动端**：仅桌面端（Electron），不考虑 iOS/Android 与响应式 Web 版本。
- **在线插件市场**：支持用户配置 MCP 与导入 Skills，但不运营在线市场、付费订阅或第三方扩展审核分发。
- **语音/视频通话**：仅文本与图片附件消息。
- **多用户协作**：单用户单机应用，不做实时多人协同。
